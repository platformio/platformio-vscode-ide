# IntelliSense System

The pioarduino IDE extension provides C/C++ IntelliSense for PlatformIO projects through two interchangeable backends. This document explains how the system works, how to configure it, and what happens under the hood.

## Supported Backends

| Backend | Extension | How it gets flags |
|---------|-----------|-------------------|
| **cpptools** (default) | [Microsoft C/C++](https://marketplace.visualstudio.com/items?itemName=ms-vscode.cpptools) | `c_cpp_properties.json` generated by `pio project init --ide vscode` |
| **clangd** | [clangd](https://marketplace.visualstudio.com/items?itemName=llvm-vs-code-extensions.vscode-clangd) | `compile_commands.json` generated by `pio run --target compiledb`, then post-processed |

## Configuration

Set the backend in VS Code settings:

```jsonc
// settings.json
{
  "platformio-ide.intelliSenseEngine": "cpptools"  // or "clangd"
}
```

On activation the extension automatically:

1. Applies backend-specific configuration defaults (e.g. disables the cpptools engine when clangd is active).
2. Warns if the required companion extension is not installed, offering to install it or switch backends.

## How It Works

### Backend Selection

```text
User setting (platformio-ide.intelliSenseEngine)
  │
  ├─ "cpptools" ──▶ Uses Microsoft C/C++ extension
  │                  Index rebuilt via: pio project init --ide vscode
  │                  Reads: c_cpp_properties.json
  │
  └─ "clangd"   ──▶ Uses clangd extension
                     Index rebuilt via: pio run --target compiledb
                     Reads: compile_commands.json (post-processed)
```

### cpptools Flow

When **cpptools** is the active backend, PlatformIO generates a `c_cpp_properties.json` with all include paths and defines. No additional post-processing is needed — the Microsoft C/C++ extension reads this file directly.

### clangd Flow

When **clangd** is the active backend, the extension performs significant post-processing on the `compile_commands.json` generated by PlatformIO. This is handled by `fixupCompileCommands()` in `src/intellisense.js`.

#### Step 1: Parse Entries

Each entry in `compile_commands.json` has a `command` string or `arguments` array, a `file` path, and a `directory`. The extension reads the file, parses the JSON, and iterates through every entry.

#### Step 2: Tokenize Commands

If an entry has a `command` string (but no `arguments` array), it is tokenized into an argv array using a platform-aware shell parser:

- **POSIX** (Linux/macOS): Handles backslash escapes, single quotes, and double quotes following GNU shell rules.
- **Windows**: Backslashes are **not** treated as escape characters, preserving paths like `C:\SDK\include`. This matches LLVM's `TokenizeWindowsCommandLine` behaviour.

After processing, entries are always written back with the `arguments` array (not `command`). clangd prefers `arguments` and this avoids all shell-quoting ambiguity.

#### Step 3: Resolve Compiler Paths

Bare compiler names (e.g. `xtensa-esp32-elf-g++`) are resolved to absolute paths by scanning PlatformIO's `packages/toolchain-*/bin/` and `packages/tool-*/bin/` directories. This is necessary so clangd's `--query-driver` glob can match the compiler and query it for built-in include paths (C++ stdlib, GCC internals).

Results are cached per invocation to avoid redundant filesystem lookups.

#### Step 4: Absolutize Include Paths

Relative include-path arguments are converted to absolute paths using the entry's `directory` as the base. The following flags are handled in both joined and separated forms:

| Flag | Joined form | Separated form |
|------|-------------|----------------|
| `-I` | `-Irelative/path` | `-I relative/path` |
| `-isystem` | `-isystemrelative/path` | `-isystem relative/path` |
| `-iquote` | `-iquoterelative/path` | `-iquote relative/path` |
| `-idirafter` | `-idirafterrelative/path` | `-idirafter relative/path` |

Flags are matched longest-prefix-first so that `-isystem` is not misinterpreted as `-I` + `system...`.

#### Step 5: Synthesize Missing File Entries

clangd uses directory proximity to match header files to compile commands. Files in directories like `usermods/` that have no `.cpp` entry nearby would get no flags and lose all IntelliSense.

To fix this, the extension:

1. Finds the project source entry with the most include flags (the "template").
2. Recursively walks the project directory for all C/C++ source and header files (`.h`, `.hpp`, `.c`, `.cpp`, `.cc`, `.cxx`, `.ino`), skipping `node_modules`, `.pio`, `.git`, `build`, and `__pycache__`.
3. For every file not already in the compilation database, creates a synthetic entry by cloning the template's `arguments` array, replacing the source file path and redirecting `-o` to `/dev/null` (or `NUL` on Windows).

#### Step 6: Configure clangd Arguments

`ensureClangdArgs()` updates the `clangd.arguments` workspace setting to include:

- **`--compile-commands-dir=<projectDir>`** — tells clangd where to find `compile_commands.json`.
- **`--query-driver=<glob>`** — allows clangd to query PlatformIO's cross-compilers for built-in system include paths. The glob covers `toolchain-*/bin/*` and `tool-*/bin/*` under the PlatformIO core directory. Without this, clangd cannot resolve system headers for embedded targets (xtensa, arm, riscv, etc.).

#### Step 7: Write Back & Notify

The modified entries are written back to `compile_commands.json` and clangd is notified to restart via the `clangd.restart` command.

## Architecture Overview

```text
Extension Activation
  │
  ├─ applyBackendConfigDefaults()    ◀── Sets VS Code config for active backend
  ├─ warnIfBackendMissing()          ◀── Prompts to install/switch if needed
  │
  └─ ProjectManager
       │
       └─ On index rebuild:
            ├─ PlatformIO CLI (pio run --target compiledb  OR  pio project init --ide vscode)
            │
            └─ If clangd:
                 ├─ fixupCompileCommands(projectDir)
                 │    ├─ Tokenize commands (platform-aware)
                 │    ├─ Resolve bare compiler → absolute path
                 │    ├─ Absolutize include paths (-I, -isystem, -iquote, -idirafter)
                 │    ├─ Synthesize entries for uncovered files
                 │    └─ Write back as arguments arrays
                 │
                 ├─ ensureClangdArgs(projectDir)
                 │    ├─ --compile-commands-dir
                 │    └─ --query-driver
                 │
                 └─ notifyRescanBackend()  ──▶  clangd.restart
```

## Platform Considerations

### Windows

- Backslashes in paths (`C:\Users\...`) are preserved during tokenization — they are not interpreted as escape characters.
- The null device for synthetic entries uses `NUL` instead of `/dev/null`.
- The `--query-driver` glob uses `\` as the path separator.

### macOS / Linux

- Standard GNU shell tokenization rules apply (backslash escapes, single/double quoting).
- The null device is `/dev/null`.
- The `--query-driver` glob uses `/` and includes `*/bin/*` to match compiler binaries.

## Troubleshooting

| Symptom | Likely Cause | Fix |
|---------|-------------|-----|
| No IntelliSense at all | Backend extension not installed | Check the notification prompt or install manually |
| Missing system headers (`<stdio.h>`, `<Arduino.h>`) | `--query-driver` not matching the compiler | Check `clangd.arguments` in workspace settings |
| IntelliSense works in `src/` but not in other directories | Files not in `compile_commands.json` | Rebuild index — synthetic entries should be generated |
| Wrong includes / stale flags | Outdated `compile_commands.json` | Rebuild project index (PlatformIO sidebar → Re-Init) |
| Paths broken on Windows | Backslash escaping issue | Ensure you are on the latest extension version |
